---
name: dsh-superagent-gitea
description: Read Gitea issues, pull requests, reviews and commit statuses, and act on Gitea with tea.
---

Workers use orchestrator_read for repository context when needed, under the resources of the ticket's Gitea Source, whose id is `$DSH_SUPERAGENT_FORGE_SOURCE` (`gitea` for the Gitea Source's own; written `<forge>` here): <forge>/issues/<number> or <forge>/pulls/<number> for the description; <forge>/issues/<number>/comments/1 for conversation comments; <forge>/pulls/<number>/comments/1 for inline review comments; <forge>/pulls/<number>/thread/<comment-id> for the review thread of any of its inline comments; <forge>/pulls/<number>/reviews/1 for reviews; <forge>/pulls/<number>/checks for CI, which on Gitea is the commit statuses (Gitea Actions report as statuses; there are no check runs, and a `warning` status neither fails nor runs). A page holds 20 entries and names next_resource while another may follow. A comment or review is `{ id, from, at, text, reply_to?, path?, line?, url }`: `reply_to` is the first comment on the same file and line, which Gitea's threads start with, and `bot: true` marks an account the Source names as automated, whose words never authorize work; Gitea itself marks no account as a bot. Follow next_offset to finish the current response; offset 0 reads afresh. Reading does not create tickets or send replies. Allowed mentions subscribe the issue/PR; subscribed comments, reviews and changed statuses of the ticket's PR arrive without further mentions.

`tea` is signed in to the agent account `$DSH_SUPERAGENT_ACCOUNT` on `$DSH_SUPERAGENT_FORGE_HOST`; pass `--repo $DSH_SUPERAGENT_REPOSITORY` to every repository command. Open the ticket's PR with `tea pr create --repo $DSH_SUPERAGENT_REPOSITORY --head <branch> --base <base> --title <title> --description <body>`, then call `orchestrator_report` with `state: progress` and `pr_number`. Never run `tea pr merge`. For anything else, `tea api` calls the API (`-X` for the method, `-f key=value` for fields), but it exits 0 even when Gitea answers an error and reads one page only: read the JSON it prints and treat a `message` field as a failure, and add `limit=50&page=<n>` to a list yourself. git pushes over HTTPS with the agent's token through dsh-superagent's credential helper; never put a token in a remote URL or a command.

Before substantial work on a new human request or review comment, call `orchestrator_ack` with its original trigger ID and a brief request-specific `text`, even within an existing ticket; the host replies once in that source thread. Do not acknowledge bots or CI.

Answer and resolve review threads as the Communication section says. An inline comment's page ends in `/pulls/<PR>/files#issuecomment-<ID>`: read <forge>/pulls/<PR>/thread/<ID>; the id of its first comment is the root ID. Reply in the thread with `tea api -X POST "repos/$DSH_SUPERAGENT_REPOSITORY/pulls/<PR>/comments/<ROOT>/replies" -f body=<text>`, and resolve it with `tea api -X POST "repos/$DSH_SUPERAGENT_REPOSITORY/pulls/comments/<ROOT>/resolve"`; check each answer as above. Do not answer a review thread with `tea comment`, which posts on the conversation. Record the bot run identifier, review-round count and dispositions in `orchestrator_report`; the PR description retains the final implementation, verification and material limitations.
